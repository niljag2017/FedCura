Strategy 1 — Centralized not yet run

Strategy 1 Centralized — all data pooled
All patient records pooled on one server. Highest accuracy but requires sharing raw patient data. Oracle upper-bound for comparison.
What is shared, how training works, and how Global AUROC 0.754 is derived Step 1 — Data split (shared across all strategies)
  2,119 patients → stratified 80/20 split (random_state=0)
  Train: 1,695 patients · Test: 424 patients (held-out, never used in training)
  Preprocessor = SimpleImputer(median) + StandardScaler fitted on train only

Step 2 — Centralized model training
  No federation. All 1,695 training patients pooled on one server.
  Objective: min_w Σᵢ ℓ(w⊤xᵢ, yᵢ) + (1/C)·‖w‖²
    ℓ = binary cross-entropy · C = 0.01 → strong L2 regularisation (λ=100)
    class_weight='balanced' → up-weights the minority readmission class
  Solver: lbfgs · max_iter=2000 · converges to global optimum
  Cross-validation: StratifiedKFold(k=5) → CV AUROC = 0.760 ± std
  Output: coef_ shape (1×23) + intercept_ shape (1,) = 24 learned parameters

Step 3 — Global AUROC = 0.754 derived (bootstrap mean)
  y_prob ← model.predict_proba(X_test)[:, 1]
    For each of the 424 test patients: probability of readmission ∈ [0, 1]
  auroc_single ← roc_auc_score(y_test, y_prob) = raw single-split score
  Bootstrap 200 resamples of (y_test, y_prob) with replacement:
    each resample: roc_auc_score(y_test[idx], y_prob[idx])
    mean of 200 scores = 0.754 · 95% CI = [0.720, 0.788]
  Raw patient data never shared. Only the final model weights could be extracted — hence "Raw data shared" label (privacy risk).

Strategy 2 — Region Federation not yet run

Strategy 2 FedAvg — one model per geographic region
Genuine FedAvg: each region trains locally, server aggregates model parameters (coef/MLP layer tensors) each round. Global model is redistributed to warm-start the next round.
What is shared & how Global AUROC 0.740 is computed Step 1 — Data split (done once before any training)
  All 2,119 patients → stratified 80/20 split (seed=0)
  Train set: 1,695 patients · Test set: 424 patients (held-out, never seen by any client)
  Preprocessor (imputer + StandardScaler) fitted on train only → shared with all clients

Step 2 — Each FL round t = 1, 2, 3
  Server → broadcasts w_global (LR: coef_ shape 1×23, intercept_ shape 1×1) to all K=5 regions
  Each region k receives w_global, injects into local model, then fits on its own X_k:
    model_k.coef_ ← w_global.coef  (warm-start: lbfgs continues from here)
    model_k.fit(X_k, y_k)  max_iter=100 local optimisation steps
    w_k ← extract_weights(model_k)  returns coef_ + intercept_ as dict
  Server aggregates via FedAvg (McMahan et al., 2017):
    α_k = n_k / Σ n_k  weight proportional to client training samples
    w_global.coef ← Σ_k α_k · w_k.coef  (23 weights averaged)
    w_global.intercept ← Σ_k α_k · w_k.intercept
  Server evaluates w_global on held-out test set → records round AUROC

Step 3 — Final Global AUROC = 0.740 (bootstrap mean)
  y_prob ← global_model.predict_proba(X_test)[:, 1]  readmission probabilities
  Bootstrap 200 resamples of (y_test, y_prob) → AUROC per resample → mean = 0.740
  95% CI [0.705, 0.775] from 2.5th–97.5th percentile of bootstrap distribution
  Raw single-split AUROC also computed; bootstrap mean used as primary metric for stability

Strategy 3 — Quality-Gated Hospital FL not yet run

Strategy 3 Quality-Gated — per-hospital FedAvg
Phase 1 screens hospitals: minimum size + local AUROC gate. Phase 2 runs genuine FedAvg on qualified hospitals only. Prevents low-quality silos from dragging down the global model.

Demo dataset note: The eICU demo has 186 hospitals but most have <15 patients each — far too few to train reliably. Only ~7 hospitals meet the minimum size criteria, and achieving AUROC≥0.75 on 8–20 patients is statistically impossible. Default gate is set to 0.55 for the demo. On the full eICU dataset (~1,000 stays/hospital), set the gate to 0.75–0.80 for meaningful quality filtering.
Two-phase quality gate — what is shared, what is filtered Phase 1 — Size filter
  Admit hospital h as candidate iff: n_h ≥ 10 AND n_pos_h ≥ 2 AND n_neg_h ≥ 2
  → Ensures enough data for a meaningful local model

Phase 1 — AUROC screening round (1 FL round)
  Each candidate hospital trains locally (from random seed weights)
  Evaluates in-sample AUROC on its own training data
  Gate: if local_auroc_h ≥ τ = 0.55 → hospital qualifies → added to set Q
  Hospitals below gate are excluded — their data never contributes to the global model

Phase 2 — FedAvg on qualifying set Q only (fl_rounds = 3)
  Server broadcasts w_global to all h ∈ Q
  Each qualified hospital: model_h.fit(X_h, y_h) → w_h
  Aggregation: w_global ← Σ_{h∈Q} (n_h / N_Q) · w_h
  Only 24 floats (coef_ + intercept_) transmitted per hospital per round — no raw data leaves

Global AUROC derivation (same as all strategies)
  y_prob ← global_model.predict_proba(X_test)[:, 1] · bootstrap 200× → mean AUROC
  AUROC is lower (~0.687) because only 359 patients are in qualifying hospitals — smaller effective training set than S1–S3

Strategy 4 — FedProx not yet run

Strategy 3 FedProx — proximal regularisation by region
FedProx (Li et al., 2020) adds a proximal term μ/2‖w−w_global‖² to each client's objective, preventing divergence when hospital data distributions are heterogeneous. Compare vs Strategy 2 (FedAvg) on the same test set.
Formula · S5 FedProx Local objective per region k: F_k(w) + (μ/2) · ‖w − w_global‖²
LR proximal update: w_k ← (1−μ)·w_local + μ·w_global
where μ = fedprox_mu = 0.01 · μ=0 → standard FedAvg
Aggregate (same as S2): w_global = Σ_k (n_k / N) · w_k

Strategy 5 — Non-IID Simulation not yet run

Strategy 3 Non-IID Simulation — Dirichlet partitioning
Dirichlet(α) partitioning simulates realistic hospital heterogeneity. Low α = extreme label skew (each client sees mostly one class). High α ≈ IID. Standard benchmark protocol from the FL literature.
Dirichlet partitioning — how label skew is simulated Purpose
  Real FL deployments have hospitals with very different readmission rates.
  Dirichlet(α) simulates this by creating clients with skewed class distributions.

Partition algorithm (data.py — dirichlet_partition)
  Separate patients into positives (readmitted) and negatives
  For each class c ∈ {0, 1}: sample proportions p_c ~ Dirichlet(α · 1_K)
    → p_c is a K-vector summing to 1 (how to split class c across K clients)
  Assign p_c[k] fraction of class-c patients to synthetic hospital k
  Result: each client has a different readmission rate — simulating real heterogeneity

α parameter controls heterogeneity
  α → 0: extreme skew — one client gets almost all readmissions, others get none
  α = 0.5 (default): moderate skew — realistic hospital heterogeneity
  α → ∞: near-IID — all clients have similar readmission rates

FL training and Global AUROC (same as S2)
  w_global ← Σ_k (n_k / N) · w_k — standard FedAvg on K=5 synthetic hospitals
  y_prob ← global_model.predict_proba(X_test)[:, 1] · bootstrap 200× → mean AUROC
  Lower AUROC than S2/S3 expected: extreme label skew makes local models misaligned with global objective

Which metrics matter for ICU readmission prediction?
AUROC (Area Under ROC) — measures rank-ordering ability across all thresholds. Good for comparing models, but insensitive to class imbalance. In ICU data (≈5–15% readmission), a high AUROC can coexist with poor minority-class recall.
Average Precision (AP) — summarises the Precision-Recall curve. Far more informative than AUROC when positives are rare. A model that flags fewer but sicker patients may have lower AUROC but higher AP.
F1 Score — harmonic mean of Precision and Recall at threshold 0.5. Useful as a single operational number, but threshold-sensitive. Consider F1 alongside AUROC/AP for deployment decisions.
Precision & Recall — precision = "of patients flagged, how many truly readmit?"; recall = "of all readmissions, how many did we catch?". Clinical context determines which to optimise (false alarm cost vs. missed readmission cost).
⚕ Clinical recommendation: For ICU readmission with class imbalance, use AUROC + AP together as primary metrics. F1/precision/recall depend on the operating threshold and should be tuned to the clinical cost trade-off (e.g. a hospital may prefer high recall at the cost of lower precision).

Architecture

Each client (hospital / region / cluster) pre-processes data using a shared global imputer + scaler fitted on the training split. The server maintains a persistent global model whose weights are broadcast to all clients before each round. Clients warm-start from those weights and return updated weights. The server runs FedAvg (weighted by n_train samples) to produce new global weights. A permanent global held-out test set (20%) is used to evaluate every strategy on identical data.

FedAvg Aggregation — models.py fedavg_aggregate()
def fedavg_aggregate(weight_list, sample_counts):
    total = sum(sample_counts)
    alpha = [n / total for n in sample_counts]  # normalised weights

    # Logistic Regression: average coef_ and intercept_
    agg_coef = np.sum(
        [np.array(w["coef"]) * a for w, a in zip(weight_list, alpha)],
        axis=0
    )
    agg_int = np.sum(
        [np.array(w["intercept"]) * a for w, a in zip(weight_list, alpha)],
        axis=0
    )
    return {"type": "lr", "coef": agg_coef.tolist(), "intercept": agg_int.tolist()}
FedProx Proximal Update — client.py local_train()
# After local model.fit(X_tr, y_tr) — FedProx proximal step (LR only)
if (self.fedprox_mu > 0
        and global_weights.get("type") == "lr"
        and self.algorithm == "logistic_regression"):

    self.model.fit(X_tr, y_tr)
    local_coef  = self.model.coef_.copy()
    global_coef = np.array(global_weights["coef"])

    # Proximal update: w ← (1−μ)w_local + μ·w_global
    mu = min(self.fedprox_mu, 1.0)   # μ = 0.01
    self.model.coef_ = (1 - mu) * local_coef + mu * global_coef
